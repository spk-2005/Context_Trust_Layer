## A. Verdict

Supported by definitive code and runtime evidence across all layers:

1. **No UI Mapping Defect**: The UI faithfully renders the backend API response and the persisted claims in PostgreSQL.
2. **Live / Audit Pipeline Divergence**: The validation audit script (`research/validation_50/run_validation.py`) bypassed Layer 4 AST document parsing, omits `hierarchical_context` when constructing evidence units, and runs an isolated extractor loop that silently suppressed 20 out of 31 candidate clauses. The live ingestion pipeline (`POST /v1/documents/upload-and-extract`) runs the full 6-layer architecture with Markdown AST hierarchy preservation, extracting all 31 clauses.
3. **Validation / Evaluation Defect (Self-Grading & Synthetic Certification)**:
   - The validation audit does not evaluate claims against human-annotated ground truth. It assigns `CORRECT_FULL_MATCH` based purely on whether the automated decision engine gate approved the claim.
   - Claim recall is mathematically simulated using a keyword regex on conditional words ("unless", "except"); when absent, recall is forced to 100.0%.
   - The "Dual-Human Adjudication" ledger (`certified_claims.json` and `ad7_dual_human_adjudication_report.json`) was generated by automated Python heuristic functions (`rater_alpha_eval` and `rater_beta_eval` in `research/adjudication_queue/interactive_review.py`) checking `trust >= 0.90`. No human ever reviewed or certified these claims.
4. **Backend Extraction & Conflict Logic Defects**: The 31 claims displayed in the live UI exhibit severe extraction defects (keyword substring collision on "administration", adverb predicates "digitally" and "also", ungrounded fallback subjects due to missing anaphora resolution, and false-positive conflict generation from comparing arbitrary regulation/standard numbers).

## E. Audit Methodology Findings

1. **Are labels independently human-created or generated by heuristics?**
   - **Answer: Generated by heuristics. No human labels exist.**
   - In `research/validation_50/run_validation.py`, `disposition` is assigned directly from `gate_eval.lifecycle_decision` (`APPROVE` -> `CORRECT_FULL_MATCH`).
   - In `research/adjudication_queue/interactive_review.py`, "Reviewer Alpha" (`rater_alpha_eval`) and "Reviewer Beta" (`rater_beta_eval`) are hardcoded Python functions that evaluate `if trust >= 0.90: return "CERTIFY"`. The output file `ad7_dual_human_adjudication_report.json` and Cohen's Kappa score are programmatically generated artifacts.

2. **Is the extractor effectively grading its own output?**
   - **Answer: Yes, 100% circular.**
   - The claims are extracted by `DomainRuleExtractor`, scored by `ClaimLifecycleDecisionEngine`, and the audit treats any score >= 0.88 as `CORRECT_FULL_MATCH`. This is why blatant defects (like `predicate: "digitally"` and `predicate: "also"`) received 99% trust scores and were declared `CORRECT_FULL_MATCH`.

3. **Is recall based on a separately established reference inventory?**
   - **Answer: No.**
   - Recall is calculated by scanning the document text for five conditional words: `\b(unless|except|provided that|subject to|with the exception of)\b`. If these words are not found (which is the case for EPCS), `missed_conditions = 0`, and Recall is mathematically forced to `valid / valid = 1.0` (100.0%).

4. **Does locator accuracy check the original source, or merely validate generated coordinates?**
   - **Answer: It validates dictionary keys only.**
   - Code: `has_valid_locator = bool(c.locator and ("line_start" in c.locator or "block_index" in c.locator))`. It never checks bounding boxes or character spans against the PDF page stream.

5. **Are any metrics hardcoded, defaulted, simulated, or inferred from trust scores?**
   - **Answer: Yes:**
     - `c.status = "verified"` and `c.verification_plugin = "TextDocumentVerificationPlugin"` are hardcoded in `run_validation.py:214-216` before gate evaluation.
     - Dual-human agreement (Cohen's Kappa) is simulated by rule-based Python heuristics.
     - Sub-labels in `MillionScaleClaimsGrid.jsx:634-640` (`EV:100% • SEM:100% • CONF:OK`) are hardcoded in the React markup.

## F. Root Causes with File Paths and Line Numbers

### Root Cause 1: DomainRuleExtractor Administration Fee Substring Match
- **File**: `backend/app/extraction/extractors/domain_rule_extractor.py`, Lines 2460–2461
- **Code**:
  ```python
  elif any(w in clean_s.lower() for w in ("fee", "restocking", "administration")) and "gift card" not in clean_s.lower():
      predicate = "may_apply_administration_fee"
  ```
- **Mechanism**: The word `"administration"` matches "Drug Enforcement Administration (DEA)", improperly categorizing a statutory agency description as an administration fee permission.

### Root Cause 2: Adverb Extraction as Predicate
- **File**: `backend/app/extraction/extractors/domain_rule_extractor.py`, Lines 2178–2200 & Line 349
- **Code**:
  ```python
  pred_words = [w for w in raw_pred_obj.split(" ") if w]
  initial_pred = pred_words[0] if pred_words else "satisfy"
  ...
  # normalize_predicate_and_modality fallback:
  return raw_p, raw_pred_obj, modality
  ```
- **Mechanism**: When a modal auxiliary is followed by an adverb ("can digitally sign", "can also use"), the tokenizer takes `pred_words[0]` ("digitally", "also"). Since these words are not in the normalization stop-list, they are returned directly as the canonical predicate.

### Root Cause 3: Anaphora Failure and Heading Fallback Misattribution
- **File**: `backend/app/extraction/extractors/domain_rule_extractor.py`, Lines 2338–2358
- **Code**:
  ```python
  raw_hier_subj = "Governance Policy"
  if hier:
      for h_candidate in reversed(hier):
          clean_h = re.sub(r"^(?:#+|\d+(?:\.\d+)*\s*[-.]?\s*)", "", h_candidate).strip()
          if clean_h and not clean_h.lower().startswith("page "):
              raw_hier_subj = clean_h
              break
  ```
- **Mechanism**: For sentences starting with pronouns ("It's available on mobile phones..."), the extractor fails to resolve the referent ("Microsoft Authenticator app") and falls back to the top document heading (`Electronic Prescriptions for Controlled Substances (EPCS)`).

### Root Cause 4: Audit Pipeline AST/Hierarchy Omission
- **File**: `research/validation_50/run_validation.py`, Lines 149–156
- **Code**:
  ```python
  units.append(ParsedEvidenceUnit.create(
      envelope_id=env.envelope_id,
      asset_id=env.asset_id,
      block_type=blk.block_type.value,
      content_text=blk.text or "",
      locator=...,
  ))
  ```
- **Mechanism**: In `run_validation.py`, `hierarchical_context` was omitted, defaulting to `[]`. This caused `DomainRuleExtractor` to assign the subject `"Governance Policy"` to all 20 non-modal sentences and suppress them via line 2295. The live pipeline preserved headings via `DocumentParser.parse`, exposing all 31 clauses.

### Root Cause 5: Spurious Numeric Value Conflict Detection
- **File**: `backend/app/conflict_engine/normalizer.py`, Lines 76–80 & `backend/app/conflict_engine/compatibility_gate.py`, Lines 286–305
- **Code**:
  ```python
  # normalizer.py:
  match = re.search(r"\b(\d+(?:\.\d+)?)\s*(business\s+days?|business_days?|[a-zA-Z%]+)?\b", search_corpus)
  
  # compatibility_gate.py:
  if key_a.value_scalar is not None and key_b.value_scalar is not None:
      if key_a.value_scalar != key_b.value_scalar:
          if not key_a.value_unit or not key_b.value_unit or key_a.value_unit == key_b.value_unit:
              return True, "INCOMPATIBLE_NUMERIC_VALUE"
  ```
- **Mechanism**: Because multiple sentences share the fallback subject `Electronic Prescriptions for Controlled Substances (EPCS)` and predicate `has_validity_rule`, the normalizer treats them as competing decision keys. It extracts whatever arbitrary number appears first in the text (e.g. Title "21", NIST "800", FIPS "140", Section "4.3"), notes that 21 != 800 != 140, and declares high-severity numeric conflicts.

## G. Minimal Proposed Repair Plan

1. **Fix `may_apply_administration_fee` keyword trigger**:
   - In `backend/app/extraction/extractors/domain_rule_extractor.py:2460`, change `any(w in clean_s.lower() for w in ("fee", "restocking", "administration"))` to require explicit fee context: `("administration fee", "admin fee", "restocking fee", "processing fee")`.
2. **Filter leading adverbs from predicates**:
   - In `backend/app/extraction/extractors/domain_rule_extractor.py:2179`, strip leading adverbs (e.g., `digitally`, `also`, `strictly`, `currently`, `automatically`) before assigning `initial_pred`, resolving the predicate to the actual verb (`sign`, `use`).
3. **Resolve immediate pronoun antecedents for sentences starting with 'It'**:
   - When a sentence begins with `It / It's / This`, check the previous sentence in the same block for a named product/feature entity before falling back to the document root heading.
4. **Prevent non-scalar document reference numbers from entering numeric conflict evaluation**:
   - In `backend/app/conflict_engine/normalizer.py:76`, guard `extract_scalar_and_unit`: do not treat regulation identifiers (`Title \d+`, `Part \d+`, `SP \d+`, `FIPS \d+`, `Level \d+`, `Section \d+`) as policy scalar values.
5. **Harmonize `run_validation.py` with the live pipeline**:
   - In `research/validation_50/run_validation.py:149`, construct evidence units with `DocumentParser.parse(env)` rather than manual unnested blocks, ensuring parity between validation runs and live ingestion.
6. **Ground Validation Audit labels in gold reference files**:
   - Discontinue self-grading in `run_validation.py`. Compare extracted claims against independent, curated gold-standard claim files (e.g. `research/gold_labels/`).
